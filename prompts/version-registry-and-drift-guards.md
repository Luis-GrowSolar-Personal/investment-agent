## Why this exists

Between 2026-08-01 and 2026-09-03 the production evaluator ran **v10+auto1**
— a machine-generated candidate that never passed a gate — while stamping
`v6` on every row it wrote. It arrived inside a commit titled "Add account
routing for new-position moves" and was caught five weeks later.

It was then rolled back on `dev` (`c514ae1`) but **not on
`sweep/db-corpus-baseline`**, which had branched on 2026-08-25. So Test 4
(~$23) and Test 6 (~$25) both measured v10+auto1 — a prompt used in neither
production nor the corpus. ~$48 and ~10M tokens producing orphan numbers.

**Root cause: version truth is asserted in four places, none authoritative,
all able to disagree** — a string constant (`versions.js`), a content header
(`EVALUATION_PROMPT.md`), a self-describing changelog (which *still* claims
v6 is "live in production as of 2026-07-05"), and git history, which differs
per branch.

**The standing priority this serves: prevent anything built later — backtest
or app — from silently drifting away from the benchmarks that were actually
proven.**

`whats_live.py`. **Seed every value from verified current truth — compute

## Step 2 — server guard

`server/routes/evaluate.js:13` reads `docs/EVALUATION_PROMPT.md` at runtime.
Verify its sha256 against the registry's promoted hash.

**Refuse to SCORE on mismatch, not refuse to boot.** 09-05 §8 proposed
boot-refusal; this deviates deliberately — taking the whole app down over a
prompt hash is a worse failure than a disabled scoring route, and Luis tests
against the deployed Railway app. So: log loudly at startup, and have the
evaluate route return a clear error naming both hashes. **Flag this
deviation from §8's wording in the wrap-up.**

**One escape hatch, or no candidate can ever be gated:** an explicit
`PROMPT_CANDIDATE=<version>` env var that must name a registered candidate.
When set, scoring proceeds **and every row written records the candidate
version, not the promoted one.** Default (unset) is refuse.

Apply the same treatment to `portfolioImport.js`'s inline prompt: hash the
literal, compare to the registry, refuse the import path on mismatch.

## Step 3 — harness guard (the one that would have saved $48)

Write **one shared helper** and call it from every driver that makes scoring
calls: `backtest_runner.py`, `backtest_from_files.py`, `eval_cache_warmer.py`,
`test4_noise_floor.py`, `test6_look_ahead.py`, `test7_score_fidelity.py`,
`auto_iterate_prompt.py`.

It must, **before the first API call**: resolve the prompt path, hash it,
compare to the registry, and **hard-fail** unless either the hash matches the
promoted artifact, or the caller passed an explicit candidate declaration
naming a registered candidate. On failure, print both hashes, the current
branch, and whether that branch diverges from `dev` on the prompt path.

Add to `CLAUDE.md` as a standing rule, and to the prompt template, so future
prompts inherit it: *any run that makes scoring calls asserts the prompt
hash against the registry before call one, or declares its candidate
explicitly.*

## Step 4 — `analysis/whats_live.py`

The one-command answer to "what version is X," so the next session does not
open an investigation. Prints:

1. every registered artifact: promoted version, expected hash, **on-disk
   hash, match/mismatch**;
2. **the current branch, and whether it diverges from `dev` on any
   registered path** — the single fact whose absence caused this incident;
3. the settled allocator configuration, from the registry rather than from a
   docstring;
4. **stale benchmarks** — every figure whose `valid_while` artifacts have
   moved, named, with what it was measured under;
5. cache-age breaches (`fundamentals_cache` at 118 days);
6. open decisions (the denominator question).

Exit non-zero if any promoted artifact mismatches, so it works in CI later.

## Step 5 — doc hygiene

1. **`EVALUATION_PROMPT.md` must stop self-describing its deployment
   status.** Line ~7 still claims v6 is "Current best (live in production as
   of 2026-07-05)" — false for five weeks, now accidentally true again.
   Content must never claim what is live; the registry is the only place
   that does. Keep the iteration changelog, remove the deployment claim.
2. **`versions.js` becomes a thin re-export of the registry**, not a
   hand-maintained constant. This deletes the bug class rather than guarding
   it. Preserve the exported names (`PROMPT_VERSION`, `MODEL_VERSION`) so
   callers are unchanged.
3. **`CLAUDE.md` gets a short "Version truth" section**: read the registry
   or run `whats_live.py`; never infer from `versions.js`, file headers, or
   `git log`.

## Step 6 — prove the guards actually fire

**A guard nobody tested is not a guard.** Test 6's driver silently dropped
two explicit instructions from its own prompt (per-call persistence and
5-way concurrency), so demonstrated behavior is required here, not claimed
implementation.

Demonstrate and show the output for each:

1. point the server guard at a deliberately wrong hash → scoring refused,
   error names both hashes;
2. `PROMPT_CANDIDATE` set to a registered candidate → scoring proceeds, row
   records the candidate;
3. `PROMPT_CANDIDATE` set to an unregistered string → refused;
4. a harness invoked on a prompt whose hash does not match → **hard-fails
   before any API call** (prove no call was made);
5. `whats_live.py` on a deliberately mismatched tree → non-zero exit,
   mismatch named, branch divergence reported;
6. `whats_live.py` on the clean tree → all match, and Test 4's and Test 6's
   floors reported **stale**.

Revert any deliberate breakage afterward and confirm the tree is clean.
